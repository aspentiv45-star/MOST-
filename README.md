# aspentiv VPN

VPN на AmneziaWG с продажей подписок через Telegram (бот @aspentivVPNbot). Во внутренних путях и службах сервера проект называется MOST (`/etc/most`, `most-bot`, папка `MOST-`) — их не переименовываем, чтобы не сломать установленные серверы.

```
Клиент (AmneziaWG) ──► Сервер в Нидерландах ──► Интернет

Клиентский бот: оплата по скриншоту, выдача конфигов
Админ-бот:      одобрение оплат, клиенты, статистика
```

## Что понадобится

1. **Сервер** (Ubuntu 22.04 / 24.04), root.
2. **Два бота** от [@BotFather](https://t.me/BotFather) (`/newbot` два раза): клиентский и админский.
3. **Ваш Telegram ID** от [@userinfobot](https://t.me/userinfobot).

## Установка

```bash
apt update && apt install -y git
git clone https://github.com/aspentiv45-star/MOST-.git && cd MOST-
sudo bash install.sh \
  --token 'ТОКЕН_КЛИЕНТСКОГО_БОТА' \
  --admin-token 'ТОКЕН_АДМИН_БОТА' \
  --admin ВАШ_ID \
  --pay 'Перевод по номеру +7 900 000-00-00, Т-Банк, Иван'
```

Если у хостинга есть свой файрвол, откройте в нём UDP-порт, который назовёт скрипт.
После установки нажмите `/start` в обоих ботах.

## Как это работает для клиента

Каждый конфиг — отдельная подписка на 30 дней (`--price`, `--router-price` в `install.sh`):
- **📱 Для себя** (телефон, ПК) — 100 ₽;
- **📡 Роутер AmneziaWG** (Keenetic 4.2+, OpenWrt) — 500 ₽: с маскировкой, работает надёжнее; к файлу
  прилагается готовая команда для Keenetic;

Обычные роутеры (TP-Link, Asus, MikroTik и др.) умеют только чистый WireGuard, а его провайдеры режут:
рукопожатие проходит, дальше трафик блокируется. Поэтому такой вариант не продаётся: бот предлагает
владельцам таких роутеров конфиги «Для устройства». Ранее выданные конфиги на чистом WireGuard (`wgr0`) продолжают работать.

**📱 Конфиг под устройство.** При покупке клиент выбирает устройство (для пробного периода бот спрашивает отдельно). iPhone и Android получают режим «только заблокированное» (российские приложения напрямую), компьютер — весь трафик: AmneziaVPN на компьютере список сетей игнорирует. Конфиги, выданные раньше, не меняются.

**Меню клиента.** Внизу три кнопки: «➕ Купить конфиг», «❓ Как подключить», «👤 Личный кабинет». В кабинете — свои кнопки: «📄 Мои конфиги», «💰 Баланс и друзья», «🎉 Розыгрыш», «🆕 Что нового», «🆘 Нужна помощь», «🧹 Почистить чат», «⬅️ Главное меню» (и коротко: конфиги, ближайший срок, баланс). Те же действия — командами в синей кнопке «Меню» Telegram: /buy, /help, /cabinet, /configs, /balance, /giveaway, /news, /support.

**Свои значки и цвета кнопок** (python-telegram-bot 22.8, Bot API 9.4). Значки — `icons/*.png` (100×100, белая иконка в розово-синем круге; рисует `icons/make.js`). `/icons` в админ-боте создаёт из них набор custom emoji `aspentiv_icons_by_<бот>` и ставит значки на кнопки по первому эмодзи текста (эмодзи из текста убирается); `/icons off` — выключить. Telegram показывает значки, только если у владельца бота Telegram Premium (или у бота есть имя с Fragment); если он откажет — бот сам выключит значки и пришлёт обычные кнопки. Цвета: «Купить», ✅ и 💳 — зелёные, 🗑, 🚫, ❌ — красные (видны в Telegram новее февраля 2026).

**🎬 Видео-инструкции.** `videos/aspentiv-iphone.mp4` и `videos/aspentiv-android.mp4` (15–17 с, вертикальные). По нажатию «⬇️ Скачать» бот сразу присылает видео для устройства конфига (если устройство не указано — когда клиент выберет iPhone или Android; компьютеру — нет; одно и то же видео не чаще раза в 2 минуты) с кнопкой «✅ Понял, больше не показывать»; кто нажал — дальше видео не приходит, а под QR/ключом остаётся кнопка «🎬 Видео-инструкция». В «❓ Как подключить» — только «🎬 Видео: iPhone / Android», роутер, режимы и «Не работает» (текстовые инструкции для iPhone, Android, компьютера и «Что купить?» оттуда убраны). Бот ищет видео в `VIDEO_DIR` (по умолчанию `videos/` рядом с bot.py, то есть `/opt/most/videos`); после первой отправки запоминает file_id Telegram. Обновить: `sudo mkdir -p /opt/most/videos && sudo cp videos/*.mp4 /opt/most/videos/`.

**📦 Все режимы сразу.** На экране скачивания кнопка «📦 Все режимы сразу» спрашивает, как прислать (🔑 ключи, 🔳 QR-коды или 📄 файлы), и присылает по одному на режим (`имя-osn`, `имя-obhod`, `имя-game`; для компьютера игровой — ПК). В приложении это отдельные туннели — клиент переключается между режимами сам, без бота. Ключ у всех один, поэтому включать можно только один туннель за раз.

**🎮 Игровой режим.** Через VPN только игры Supercell (Brawl Stars, Clash Royale, Clash of Clans и др.: `GAME_NETS` и адреса из DNS `GAME_HOSTS`). Ещё игры, у которых в России закрыт вход или покупки (`GAME_SERVICES`: Call of Duty Mobile, Pokémon GO, Fortnite, EA, Blizzard, Minecraft/Xbox, Riot, Ubisoft, PlayStation, Nintendo), — только серверы входа и API, по адресам из DNS (до `GAME_IP_MAX`=4 с имени), чтобы список оставался коротким. App Store и Google Play идут мимо VPN: из туннеля вырезаются подсети /24 с адресами магазина (`STORE_HOSTS`), пока список не длиннее `GAME_LIST_MAX`=250, а подключение идёт напрямую на основной сервер на UDP `GAME_PORT` (по умолчанию 443 — нужен `alt-port.sh 443`), минуя вход в России: пинг ниже. Если у оператора прямое подключение не проходит — режим «только заблокированное».

**🔀 Режимы «⚡️ Основной» (`smart`) и «🛡 Обход белых списков» (`full`, через вход в России).** «Основной» сейчас (по умолчанию, `SMART_FULL=1`) это весь трафик через VPN, но подключение сразу к основному серверу на UDP `GAME_PORT`, без входа в России; российские адреса основной сервер сам отправляет через российский выход (`ru-route.sh`). Списки сервисов и их обновление не используются. Старое поведение со списком (ниже) — `SMART_FULL=0` в bot.env. В «📄 Мои конфиги» → «🔀 Режим» клиент может переключить конфиг:
через VPN пойдут только Telegram, YouTube/Google, Meta, X, Discord, Twitch, Reddit (около 80 сетей,
`SMART_NETS` в `bot/bot.py`), а российские сайты, банки и игры — напрямую с устройства. Больше ~100 сетей
приложения Amnezia обрабатывают плохо. Режим работает в AmneziaWG; AmneziaVPN на компьютере его игнорирует.

**🎁 Пробный период.** Новый клиент один раз может взять конфиг для устройства бесплатно на 3 дня
(«➕ Купить конфиг» → «🎁 Попробовать бесплатно»): без оплаты и одобрения, администратору приходит уведомление.
Перед окончанием бот напоминает. Чтобы продолжить, клиент нажимает «🔄 Продлить», платит, и **тот же конфиг**
работает дальше. Срок пробного: `--trial N` в `install.sh` (`--trial 0` — выключить).

**📶 Настройка под оператора.** При покупке и пробном периоде бот спрашивает мобильного оператора (МТС, Билайн, МегаФон, Т2, Yota, Т-Мобайл, только Wi-Fi, другой) и подстраивает под него маскировку конфига: число и размер пакетов-пустышек (`Jc`, `Jmin`, `Jmax`) и маскирующий пакет `I1` в форме ответа DNS. Эти параметры задаёт только клиент, сервер менять не нужно. Сменить оператора: «📄 Мои конфиги» → «📶 Оператор», бот пришлёт новый файл с теми же ключами. Профили — `PROFILES` в `bot/bot.py`. Сервер ставит MTU 1280 и ограничивает TCP MSS до 1240 (`most-abuse`), чтобы на мобильном интернете не зависали сайты.

Покупка идёт по шагам: «➕ Купить конфиг» → «📱 Для устройства» или «📡 Для роутера» → конкретное устройство
(iPhone, Android, компьютер) или тип роутера → подробная инструкция и кнопка «💳 Купить».

Кнопка «❓ Как подключить» открывает те же инструкции: «🛒 Что купить?», iPhone, Android, компьютер,
роутер (Keenetic, OpenWrt) и «🆘 Не работает».

1. «➕ Купить конфиг — 100 ₽» → реквизиты → клиент присылает скриншот.
2. Скриншот приходит в админ-бот с кнопками «✅ Одобрить» и «❌ Отклонить».
3. После одобрения клиенту сразу приходит новый конфиг на 30 дней. Второе устройство — ещё одна покупка.
4. «📄 Мои конфиги»: у каждого конфига свой срок и кнопки «⬇️ Скачать», «🔄 Продлить — 100 ₽», «🗑 Удалить». Кнопка «✏️ Название» даёт конфигу своё имя («Телефон мамы»), оно видно в боте; если имя латиницей без пробелов до 12 символов, так же называется и файл, то есть туннель в приложении. Кнопка «🏓 Пинг» показывает, подключён ли конфиг сейчас, трафик и пинг от сервера до устройства (у администратора такая же кнопка в «👥 Клиенты»).
5. За 3 дня и за 1 день до конца бот напоминает про конкретный конфиг. Когда срок вышел, конфиг удаляется
   с сервера: VPN через него перестаёт работать. После продления тот же файл снова работает, переустанавливать не нужно.

Один клиент может держать до 3 конфигов (`--max N` в `install.sh`). Конфиги администратора бессрочные.

**💳 Сроки, баланс и приглашения.**
- При оплате устройства клиент выбирает срок: 1 месяц — `PRICE` (150 ₽), 3 месяца — `PRICE3` (по умолчанию −20%, 360 ₽) или год — `PRICE12` (−35%, 1170 ₽). Роутер (до 5 устройств) — `ROUTER_PRICE` (500 ₽), только месяц. Покупка — только с баланса: не хватает — «➕ Пополнить» (предложит ровно недостающую сумму), после пополнения конфиг оплатится сам. После одобрения доступа бот сразу предлагает пополнить баланс.
- Оплата — только через баланс: на экране оплаты баланс и «✅ Оплатить с баланса» или, если не хватает, «➕ Пополнить» → выбор суммы (150, 300, 500, 1000 ₽ или своя). Реквизиты — только на экране пополнения. Пополнение, привязанное к покупке, после одобрения админом сразу оплачивает её с баланса.
- «💰 Баланс и друзья»: пополнение от `TOPUP_MIN` (150 ₽) — клиент выбирает сумму и платит через Ckassa (СБП или карта), и баланс пополняется автоматически. Без Ckassa клиент переводит по реквизитам и присылает скриншот, админ одобряет. С баланса покупка и продление — сразу, без проверки («💰 Оплатить с баланса»), админам приходит уведомление.
- Приглашения: у клиента есть ID и ссылка `t.me/бот?start=ref_ID`. Друг засчитывается, когда впервые оплатит VPN (переводом или с баланса). За каждых `REF_NEED` (3) друзей — `REF_DAYS` (30) дней к конфигу, который кончается раньше всех (нет конфигов — `PRICE` на баланс).
- При закрытом доступе (`ACCESS=closed`) новичок присылает ID пригласившего (или приходит по ссылке) либо нажимает «🙋 Меня никто не пригласил» — после этого админу уходит запрос доступа (с именем пригласившего или «👤 Без приглашения»). При открытом доступе указать друга можно в «💰 Баланс и друзья» → «✏️ Меня пригласил друг» (пока нет оплат).
- В карточке клиента у админа — баланс, сколько привёл и от кого пришёл; в статистике — сумма на балансах (оплаты с баланса в выручку второй раз не идут).

- «🆘 Нужна помощь»: кнопки «↩️ Вернуть средства», «🔧 Конфиг не работает», «✍️ Свой вопрос» (или сразу написать). «↩️ Вернуть средства» есть и в «Как подключить»: клиент выбирает причину (пополнил ошибочно, конфиг не работает, свой вопрос), и создаётся обращение с этой темой. Возврат звёзд — `/refund`, возврат перевода — вручную, после этого спишите сумму с баланса клиента через «💰 Выдать деньги», указав её с минусом (например, -150).

## Админ-бот

Кнопки:
- **⏳ Оплаты**: неразобранные скриншоты с кнопками «Одобрить» и «Отклонить». В каждой оплате видно,
  за что она: новый конфиг или продление конкретного.
- **👥 Клиенты**: выбор группы — «🟢 Действуют» (сначала те, у кого срок кончается раньше; внутри — «🔌 Подключены сейчас», «💤 Не подключены» с временем последнего подключения и «📋 Все»), «⚪️ Закончились / не оплачены», «👤 Без конфига». Сверху «🙋 Ждут решения» — запросы доступа и непроверенные оплаты (то же, что «⏳ Оплаты»). В «⚪️ Закончились / не оплачены» — «🗑 Удалить все неоплаченные» (с подтверждением; конфиги с оплатой на проверке не трогаются) и «⏰ Автоудаление через 5 дн.»: когда включено, бот сам удаляет конфиги, у которых срок кончился (или которые не оплачены) больше 5 дней назад, и сообщает клиенту. По одному сообщению на клиента со всеми его конфигами; кнопки «➕ Продлить» (на 7, 30, 90, 365 дней или своё число), «⛔️ Отключить», «🏓 Пинг» и «📋 ID» (копирует ID клиента). Если конфигов несколько, бот спросит, какой продлить, отключить или проверить.
- **💰 Выдать деньги**: пришлите ID клиента и сумму (`123456789 300`; списать — `123456789 -100`), и деньги придут ему на баланс. То же — кнопка «💰 Деньги» в карточке клиента.
- **📊 Статистика**: оплаченные конфиги, выручка, кто подключался и сколько трафика.
- **🎉 Розыгрыш**: число победителей (1–10 или своё до 100), приз (+3/7/14/30 дней или своё до 365), начало (сейчас, через 1 ч, 3 ч, сутки) и длительность (1 ч – 3 дня). Объявление получают все клиенты; если начало позже — кнопка «🔔 Напомнить» (в начале эти люди получат сообщение, а объявления у всех превратятся в «🎉 Участвовать»). Кто пришёл позже, найдёт розыгрыш в меню клиента — кнопка «🎉 Розыгрыш». В конце бот случайно выбирает победителей: один конфиг — дни добавляются к нему, несколько — победитель сам выбирает кнопкой, какой продлить, нет конфигов — новый. Админ может «▶️ Начать сейчас», «⏹ Завершить сейчас» или «❌ Отменить».
- **Продление в одно нажатие.** Напоминания о сроке (за 3 дня, за сутки, «закончился») приходят с кнопками: «✅ Продлить на … с баланса» — если денег хватает (сразу, без проверки), и «🔄 Продлить / пополнить баланс».
- **Кто ждёт решения.** В приветствии админ-бота (/start, «🧹 Почистить чат») — строка «🙋 Ждут решения — запросов доступа: N, оплат на проверке: M» или «✅ Никто не ждёт». Если запрос доступа или оплата ждут дольше часа, бот напоминает (не чаще раза в 3 часа) с кнопкой «🙋 Показать».
- **🚫 Блокировка клиента** (карточка клиента в «👥 Клиенты»): «🚫 Заблокировать» на 1, 7, 30 дней или навсегда — конфиги клиента убираются с сервера (VPN не работает), бот на любое его действие отвечает «доступ заблокирован»; «✅ Разблокировать» — сразу возвращает. Срочная блокировка снимается сама по сроку (проверка раз в 10 минут), клиенту приходит сообщение. «🔓 Снять бан за спам» — появляется, если клиенту запрещены обращения. Срок конфигов во время блокировки идёт.
- **💸 Прогноз**: ближайшая оплата (когда, кто, сколько), суммы за 7 и 30 дней и «если продлят все». Ожидаемая цена — как клиент платил за этот конфиг в прошлый раз (месяц или 3 месяца), иначе обычная. Кончившиеся больше 3 дней назад не считаются. «🚫 Исключения» — отметить клиентов, которых не считать (друзья, бесплатные).
- **📤 Разослать конфиги**: напишите, что поменялось, и выберите, что разослать. **Режим** (⚡️ Основной, 🛡 Обход белых списков, 🎮 Игровой: телефон или ПК) — клиенты с конфигами для устройств получат «Обновился режим … Вы им пользуетесь?» с кнопками «✅ Пользуюсь» и «❌ Не пользуюсь»; «Пользуюсь» переводит конфиг в этот режим (при нескольких конфигах — выбор какого) и открывает скачивание. **📦 Все сразу** — кнопка на каждый активный конфиг, файл по нажатию.
- **📢 Оповестить об обновлении**: напишите, что нового, и всем клиентам придёт «📢 Обновление от ДД.ММ.ГГГГ — ваш текст». Запись сохраняется, клиенты видят историю по кнопке «🆕 Что нового» (рассылки конфигов туда тоже попадают).
- **🖥 Серверы**: состояние основного сервера (VPN, подключены сейчас, процессор, память, диск, канал), входа и туннеля для российских сайтов, блокировки рекламы. Раз в 2 минуты бот проверяет это сам и пишет администратору, если что-то сломалось («🔴 …») и когда починилось («🟢 …»).
- **🗳 Опрос**: пришлите вопрос и варианты (каждый с новой строки) — всем клиентам придёт опрос с кнопками. Проголосовав, клиент сразу видит результаты в процентах (голос можно поменять). У вас — общие результаты, кнопки «🔄 Обновить», «🔒 Закрыть» и «🆕 Новый опрос».
- **📨 Жалобы**: обращения клиентов (клиент жмёт «🆘 Нужна помощь» и описывает проблему). У каждого кнопки «💬 Ответить», «🎁 Дать конфиг» (на сколько дней — пишете сами), «💸 Вернуть деньги» (бот просит у клиента реквизиты и присылает их вам с кнопкой «✅ Деньги отправлены») и «❌ Отклонить». Пока обращение открыто, всё, что клиент пишет и присылает (несколько скриншотов, альбом), попадает в него, а под сообщением «Обращение принято» есть кнопки «✅ Вопрос решён» и «🏠 В меню». Скриншот считается оплатой только после «💳 Купить» или «🔄 Продлить». В списке только обращения, которые ждут вашего действия: после ответа обращение пропадает, а у клиента появляются кнопки «✅ Вопрос решён», «❓ Задать ещё вопрос» и «🏠 В меню». Дополнительный вопрос возвращает обращение в список со всей перепиской. Кнопка «🚫 Спам» закрывает обращение и запрещает клиенту новые обращения на 10 минут, 1 час, 1 день или своё число минут: клиенту приходит сообщение о блокировке, а при попытке написать снова — сколько ещё ждать.

**Чистый чат.** При нажатии кнопки меню бот удаляет само нажатие и свой прошлый экран, так что в чате остаётся только текущий. Файлы конфигов, QR-коды, оплаты, оповещения и переписка поддержки не удаляются. «🆕 Что нового» показывает последние 3 обновления и кнопку «📜 Показать все». Под каждым сообщением с кнопками есть «✖️ Закрыть»: оно удаляет это сообщение. Под файлом конфига тоже «✖️ Закрыть», под QR-кодом «✅ Готово» убирает и QR, и файл (кнопки нет у заявок, оплат и обращений — их терять нельзя).

Кнопка «🧹 Почистить чат» есть в обоих ботах: бот удаляет сообщения чата и заново присылает приветствие с меню (Telegram позволяет ботам удалять только сообщения за последние 48 часов).

Команды: `/send ID текст` (написать клиенту), `/broadcast текст` (написать всем).

Если что-то сломается, например не получится создать конфиг, текст ошибки придёт в админ-бот.

Реквизиты (номер) сразу не показываются: клиент нажимает «📲 Запросить реквизиты», админу приходит «📲 Запрос реквизитов» с кнопками «✅ Показать реквизиты» и «❌ Отказать». После одобрения бот присылает клиенту реквизиты, они действуют 24 часа, а следующий скриншот засчитывается как оплата этого пополнения. Повторный запрос возможен через 6 часов, если админ не ответил. Реквизиты хранятся в `/etc/most/pay.txt`. Их можно менять в любой момент, перезапуск не нужен.

### Автоматическое пополнение через Ckassa

Если заданы ключи Ckassa, при пополнении клиент выбирает «🏦 Оплатить по СБП» или «💳 Оплатить картой». Бот создаёт платёж и даёт ссылку. После оплаты баланс пополняется сам: бот каждые 30 секунд спрашивает у Ckassa статус платежа, свой HTTPS-сервер для этого не нужен. Если клиент нажимал «Пополнить» с экрана покупки, бот сразу оплачивает покупку с баланса. Админу приходит уведомление «💳 Ckassa: +N ₽». Если `pay.txt` есть, остаётся кнопка «📷 Перевод со скриншотом» для старого способа.

Ключи берутся в личном кабинете Ckassa: «Заявка» → «Подключения». Их нужно дописать в `/etc/most/bot.env` (в репозиторий их не кладите):

```
CKASSA_SHOP_TOKEN=...
CKASSA_SEC_KEY=...
CKASSA_SERVICE=111-11111-1        # код услуги
CKASSA_PROP=ЛИЦЕВОЙ_СЧЕТ          # название реквизита вашей услуги (как в ЛК); в него бот пишет номер заказа
# CKASSA_PAYTYPES=sbp,card        # способы оплаты и их порядок
# CKASSA_URL=https://demo-api2.ckassa.ru/api-shop   # тестовый контур
```

После этого выполните `sudo systemctl restart most-bot`. Пока ключей нет, пополнение работает по-старому.

### Оплата звёздами Telegram


Звёздами пополняют баланс (покупка — только с баланса): на экране пополнения есть кнопка «⭐️ Оплатить звёздами». Бот выставляет счёт в звёздах, и после оплаты баланс пополняется сразу. Если пополнение было для покупки, бот сразу её оплачивает. Минимум, как и для перевода, `TOPUP_MIN`. Курс: звезда стоит `STAR_PRICE=1.5` ₽, а пополнять звёздами на `STARS_DISCOUNT=10` % дешевле, чем переводом: 150 ₽ = 90 ⭐️, 300 ₽ = 180 ⭐️, 1000 ₽ = 600 ⭐️. Чтобы задать рубли баланса за звезду вручную, укажите `STAR_RUB=…`.1`. Строка `STARS=0` выключает оплату звёздами. Подсказку, где купить звёзды, можно включить строкой `STARS_SHOP=имя_бота` (по умолчанию выключена). Админу приходит уведомление с готовой командой возврата: `/refund ID charge_id` возвращает звёзды и списывает сумму с баланса. Звёзды копятся на боте, вывести их можно через @BotFather → бот → Payments (Fragment, в TON).

## Российские сайты с включённым VPN

Многие российские сервисы (банки, Госуслуги, маркетплейсы) не открываются с зарубежных IP. Есть два режима.

**Через российский сервер (рекомендуется, работает в любом приложении, включая AmneziaVPN).**
Клиенты пускают в VPN весь трафик, а основной сервер сам отправляет трафик к российским адресам
через российский сервер. Российские сайты видят российский IP, остальное идёт из Нидерландов.
Telegram, WhatsApp/Instagram/Facebook, YouTube/Google и X всегда идут из Нидерландов.

```
Клиент ──► NL ──► Telegram, YouTube, ...
            └───► RU-сервер ──► Ozon, WB, VK, Госуслуги
```

1. На **российском сервере**:
   ```bash
   cd MOST- && git pull && sudo bash ru-node.sh --nl-ip IP_ОСНОВНОГО
   ```
   В конце скрипт напечатает команду `sudo bash ru-route.sh '...'`.
2. Выполните эту команду на **основном сервере** в папке `MOST-`.
3. Клиентам нужно один раз скачать конфиг заново в «📄 Мои конфиги».

Отключить: `sudo bash ru-route.sh off` (конфиги снова станут раздельными).

**Режим доменов: через Россию только .ru** (`ru-domains.sh`, на основном сервере после `ru-route.sh`). Обычно через Россию идут все российские IP. В режиме доменов через Россию идут только сайты на `.ru`, `.рф` и `.su`, а всё остальное идёт из Нидерландов, даже если сервер сайта в России. DNS-запросы клиентов перехватывает DNS сервера `most-rudns` (порт 5354): он запоминает адреса .ru-сайтов, а узнаёт их у Яндекс DNS через туннель, чтобы получить российские адреса. Шифрованный DNS публичных серверов (Cloudflare, Google, Quad9, AdGuard) для клиентов закрыт, поэтому браузер возвращается к обычному DNS. Конфиги клиентов менять не нужно.
```
sudo bash ru-domains.sh        # включить
sudo nano /etc/most/ru-domains.txt && sudo bash ru-domains.sh   # добавить свои домены (vk.com и т. п.)
sudo bash ru-domains.sh off    # вернуть «все российские IP»
```
Если туннель в Россию упал, сторож его выключает, и все сайты, включая .ru, идут из Нидерландов.

**Сторож туннеля** (`most-ru-watch`, ставится вместе с `ru-route.sh`; на уже настроенный сервер — `sudo bash ru-route.sh watchdog`). Раз в минуту пингует российский сервер через туннель. Перестал отвечать (например, соединение заблокировали по дороге) — перезапускает туннель, он выходит с нового порта. Не помогло — выключает его, и российские сайты идут из Нидерландов, а не зависают у всех клиентов; потом раз в минуту пробует поднять снова. Журнал: `/var/log/most-ru-watch.log`.

**Раздельный туннель (без российского сервера).** В конфиге российские сети исключены из VPN
и идут напрямую с IP устройства. Работает в AmneziaWG, но **не работает в AmneziaVPN**:
она не поддерживает раздельный туннель в импортированных конфигах, и российские сайты не открываются.
Список сетей бот обновляет раз в сутки (`python3 bot/split.py` показывает, как пойдут конкретные сайты).

Свои сети «всегда через Нидерланды» можно добавить в `/etc/most/force_vpn.txt` (по одной на строку)
и выполнить `systemctl restart most-bot` (и `/usr/local/sbin/most-ru-route update`, если включён первый режим).

## Обход белых списков (вход через РФ)

Когда включены белые списки, мобильный интернет пропускает только разрешённые адреса.
Нужен «вход»: российский сервер, IP которого в этих списках есть (например, Yandex Cloud или VK Cloud).
Он ничего не шифрует и не хранит, а только пересылает трафик на основной сервер.

```
Клиент ──► вход (Yandex Cloud) ──► основной сервер NL ──► Интернет
```

1. На **сервере-входе** (Ubuntu), где ПОРТ — UDP-порт AmneziaWG основного сервера:
   ```bash
   apt update && apt install -y git
   git clone https://github.com/aspentiv45-star/MOST-.git && cd MOST-
   sudo bash relay.sh --to IP_ОСНОВНОГО:ПОРТ
   ```
   В облаке разрешите этот UDP-порт в группе безопасности.
2. На **основном сервере**:
   ```bash
   cd MOST- && git pull && sudo bash install.sh --relay IP_ВХОДА
   ```

Теперь бот выдаёт один файл `vpn1.conf`, который подключается через вход: прямое подключение
к зарубежному серверу российские провайдеры часто режут. Чтобы бот выдавал ещё и прямой конфиг
(`vpn1-nl.conf`), добавьте `SEND_DIRECT=1` в `/etc/most/bot.env` и выполните `systemctl restart most-bot`.
Уже выданные конфиги клиент может скачать заново в «📄 Мои конфиги», ключи останутся прежними.

Гарантии нет: списки у операторов разные и меняются. Прежде чем обещать клиентам обход,
проверьте `-wl` конфиг на мобильном интернете при включённых списках.

## Если заблокировали IP основного сервера

Признак: VPN у всех перестал работать, а с входа `for i in $(seq 20); do timeout 3 bash -c "</dev/tcp/IP/22" && echo ok || echo FAIL; done`
показывает много FAIL. Возьмите у хостинга новый IP и на **входе** выполните:

```bash
cd MOST- && git pull && sudo bash switch-ip.sh НОВЫЙ_IP
```

Скрипт проверит адрес из России (нужно 20 из 20), переключит пересылку и откроет новому адресу туннель
для российских сайтов. Потом на основном сервере — команда, которую он напечатает (адрес для бота).
Клиентам ничего менять не нужно.

## Если режут UDP на порт основного сервера

Бывает, что TCP к основному серверу из России проходит, а AmneziaWG (UDP) на его обычный порт —
нет. Тогда вход шлёт трафик на основной сервер на UDP 443 (как QUIC), клиентам ничего менять не нужно:

1. На **основном сервере**: `cd MOST- && git pull && sudo bash alt-port.sh 443`.
2. На **входе**: `cd MOST- && git pull && sudo bash relay.sh --to IP_ОСНОВНОГО:ПОРТ=443,ПОРТ_РОУТЕРОВ`
   (например `--to 104.249.40.115:50967=443,50968`).

Убрать: `sudo bash alt-port.sh off` на основном сервере и `relay.sh --to IP:ПОРТ,ПОРТ_РОУТЕРОВ` на входе.

Проверить, режут ли адрес основного сервера, — с входа:
`IP=...; for i in $(seq 20); do timeout 3 bash -c "</dev/tcp/$IP/22" 2>/dev/null && echo ok || echo FAIL; done | sort | uniq -c`
(нужно 20 ok; если у хостинга можно бесплатно сменить IP — меняйте, пока не будет 20 из 20).

## Если режут канал «вход → основной сервер»

ТСПУ умеет распознавать AmneziaWG, который вход пересылает за границу: телефоны до входа
достают, а до основного сервера пакеты не доходят. Тогда канал между серверами заворачивается
в VLESS Reality — для DPI это обычный HTTPS (TCP 443, сертификат чужого сайта). Клиенты
по-прежнему подключаются ко входу по AmneziaWG, конфиги менять не нужно.

1. На **основном сервере**: `cd MOST- && git pull && sudo bash xray-link.sh server`
   (в конце напечатает команду для входа).
2. На **входе**: `cd MOST- && git pull && sudo bash xray-link.sh client 'СТРОКА-КЛЮЧ'`.

Вернуть обычную пересылку на входе: `sudo bash xray-link.sh off`.

## Блокировка рекламы

`sudo bash adblock.sh` на основном сервере ставит DNS-сервер (dnsmasq на адресе VPN-сервера, 10.8.0.1),
который не пускает к доменам рекламы и слежки — фильтр AdGuard DNS, в нём и российские рекламные сети.
Список обновляется раз в сутки. Бот выдаёт конфиги с этим DNS (режимы «Весь трафик» и «Только
заблокированное»); клиент может выключить блокировку у своего конфига кнопкой «🛡 Реклама».
Старые файлы конфигов нужно скачать заново. Рекламу внутри YouTube так не убрать: она идёт с тех же
серверов, что и видео. Выключить: `sudo bash adblock.sh off`.

## Сайт для платёжного сервиса

Платёжные агрегаторы (например, Antilopay) требуют сайт на своём домене: цены в рублях, порядок заказа и оплаты,
условия возврата, политика обработки персональных данных, контакты с ИНН и адресом. Всё это — в папке `site/`.

1. Купите домен и пропишите A-запись на IP сервера, где будет сайт (лучше московского).
2. На этом сервере: `cd MOST- && git pull && sudo bash site-setup.sh` — создаст `/etc/most/site.env`.
3. Впишите туда свои данные (ФИО, ИНН, ОГРНИП, адрес, телефон, email, домен) и запустите скрипт снова:
   он соберёт сайт, поставит nginx и бесплатный сертификат HTTPS.

Личные данные хранятся только в `/etc/most/site.env` на сервере, в репозиторий они не попадают.

## Туннель для российских сайтов: потери и смена порта

Бот раз в 10 минут проверяет потери в туннеле `awg1` (30 пингов до 10.66.0.1). Две плохие проверки подряд (≥ `TUN_ALERT_LOSS`, 5%) — сообщение админу с кнопками «🔄 Подобрать другой порт» и «✅ Оставить» (не напоминать 6 часов); когда потери уйдут — «🟢 снова без потерь». Потери и порт видны в «🖥 Серверы».

Чтобы бот мог менять порт сам, на российском сервере один раз:

```bash
sudo bash ru-ports.sh 104.249.40.115   # UDP 1024–9999 от основного сервера -> порт туннеля (most-ru-ports)
```

и на основном `TUN_PORT_RANGE=1024-9999` в bot.env. «Подобрать» пробует до 8 случайных портов из диапазона (по 20 пингов), оставляет лучший и записывает его в `awg1.conf`; клиентам ничего менять не нужно. Порт по умолчанию — 8053: на 443 и высоких портах потери были 10–34%. Сменили IP основного сервера — `ru-ports.sh` с новым IP.

## Диагностика скорости

`sudo bash diag.sh` (на основном и на входе) — короткий отчёт: нагрузка и softirq, буферы UDP, BBR, очередь, conntrack, потери пакетов (UDP-буферы, softnet, отброшенные на интерфейсах), MTU, подключённые клиенты, скорость канала сервера без VPN (Cloudflare), пинг и потери до второго сервера и по туннелю для российских сайтов. `sudo bash diag.sh fix` — сетевые настройки для скорости (буферы 32 МБ, BBR + fq, очередь, conntrack), сохраняются в `/etc/sysctl.d/99-most-speed.conf`.

## Бэкап

Каждую ночь (в `BACKUP_HOUR`, по умолчанию 4:00 по `TZ_NAME`) бот присылает админам `aspentiv-backup-ДАТА.zip`: база бота (`state.json` — клиенты, сроки, балансы, оплаты, розыгрыши), реквизиты и конфиги VPN-сервера (`awg0.conf` с ключом сервера, `awg1.conf`, `wgr0.conf`). Токенов ботов в нём нет. `/backup` — прислать сейчас.

Восстановить базу: `/restore` → прислать файл бэкапа → «✅ Восстановить» (текущая база сохраняется копией `state.json.before-restore-…`, сервер VPN сразу обновляется).

Переезд на новый сервер так, чтобы клиентам не пришлось менять конфиги: поставить MOST (`install.sh`), заменить в `/etc/amnezia/amneziawg/awg0.conf` строки `[Interface]` (PrivateKey, ListenPort, Jc…H4) на те, что в бэкапе, перезапустить `awg-quick@awg0`, затем `/restore` в админ-боте и сменить IP в `ENDPOINT_HOST` (или на входе — `switch-ip.sh`).

## Защита от рисков

- **Доступ по приглашению** (по умолчанию). Новый человек нажимает `/start`, и в админ-бот приходит
  запрос «✅ Пустить / ❌ Отказать». Пока не пустите, купить он ничего не может. Кто уже платил, остаётся
  с доступом. Открыть бот для всех: `sudo bash install.sh --access open`.
- **Торренты и спам заблокированы.** Клиентам запрещены протокол BitTorrent (трекеры, DHT, magnet)
  и исходящая почта на порт 25: это главные причины жалоб хостеров. Сервис `most-abuse`.
  Зашифрованные торренты так не ловятся полностью, но обычные клиенты с настройками по умолчанию не работают.

## Безопасность

- Токены, ключи и база клиентов хранятся только на сервере: `/etc/most/`, `/var/lib/most/`, `/etc/amnezia/amneziawg/`.
- Репозиторий публичный, ничего секретного в него не добавляйте.
