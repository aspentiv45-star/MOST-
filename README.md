# MOST

Мост через российский сервер к нидерландскому серверу на 3X-UI.

```
Телефон/ПК  ──►  RU-сервер (MOST, Xray)  ──►  NL-сервер (3X-UI)  ──►  Интернет
```

Клиент подключается к российскому IP: такое соединение реже блокируется и обычно
работает стабильнее, чем прямое подключение к зарубежному серверу. Российский сервер
передаёт трафик на нидерландский.

## Режимы

| Режим | Как работает | Когда выбирать |
|---|---|---|
| `chain` (по умолчанию) | На RU-сервере поднимается свой VLESS + Reality с маскировкой под российский сайт. Оттуда трафик идёт на NL-сервер по вашей ссылке из 3X-UI. Российские сайты (`.ru`, `.su`, `.рф`, российские IP) открываются напрямую с RU-сервера. | Почти всегда |
| `forward` | Простой проброс TCP/UDP-порта на NL-сервер. Клиент использует ту же ссылку из 3X-UI, только с IP российского сервера. | Нужно максимально просто, ничего не менять на клиентах |

## Установка

На **российском** сервере (Ubuntu 20.04+/Debian 11+), от root:

```bash
git clone https://github.com/aspentiv45-star/MOST-.git
cd MOST-
sudo bash install.sh --link 'vless://...ссылка из 3X-UI...'
```

Ссылку берите в 3X-UI на **нидерландском** сервере: *Inbounds* → нужный inbound → у клиента
кнопка *QR / Info* → скопировать ссылку.

В конце скрипт напечатает **новую ссылку для клиента** и сохранит её в
`/root/most-client.txt`. Добавьте её в v2rayN, v2RayTun, Hiddify, Streisand или NekoBox.

### Параметры

```
--mode chain|forward   режим (по умолчанию chain)
--port N               порт на RU-сервере (по умолчанию 443)
--sni домен            сайт для маскировки Reality (по умолчанию ya.ru)
--ip адрес             внешний IP RU-сервера (по умолчанию определяется сам)
--no-ru-direct         пускать и российские сайты через Нидерланды
```

Примеры:

```bash
# Простой проброс на порт 8443
sudo bash install.sh --link 'vless://...' --mode forward --port 8443

# Маскировка под другой сайт
sudo bash install.sh --link 'vless://...' --sni www.vk.com
```

Сайт для `--sni` должен поддерживать TLS 1.3 и HTTP/2. Скрипт проверяет это сам
(`xray tls ping`), результат виден в выводе.

## Поддерживаемые ссылки из 3X-UI

- Протоколы: `vless://` (в том числе с VLESS Encryption `mlkem768x25519plus`), `vmess://`, `trojan://`
- Транспорт: `tcp` (raw), `ws`, `grpc`, `xhttp`, `httpupgrade`
- Безопасность: `reality`, `tls`, `none`

## Проверка и обслуживание

```bash
sudo bash check.sh             # проверить, что трафик выходит в Нидерландах
systemctl status xray          # работает ли мост
journalctl -u xray -f          # логи
cat /root/most-client.txt      # ссылка для клиента
sudo bash install.sh --link '...'   # переустановить с новой ссылкой (старый конфиг сохраняется в .bak)
sudo bash uninstall.sh         # удалить
```

## Если не работает

1. **Порт занят.** Скрипт об этом скажет. Выберите другой порт через `--port 8443`.
2. **Файрвол хостинга.** Откройте порт в панели провайдера RU-сервера.
3. **Проверьте, что NL-сервер доступен с RU-сервера:** `curl -v telnet://IP_NL:ПОРТ` должен соединиться.
4. **Логи:** `journalctl -u xray -n 50`.

## Безопасность

- В репозитории нет ключей. Конфиг генерируется прямо на сервере в `/usr/local/etc/xray/config.json`.
- Не выкладывайте ссылки подключения и `config.json` в открытый доступ.
- По желанию в 3X-UI на NL-сервере можно разрешить подключения только с IP российского сервера.
